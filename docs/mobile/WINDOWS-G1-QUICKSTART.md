# Windows 11 quickstart for DumanMessenger G1

**Purpose:** Get the owner’s Windows 11 x64 machine ready for Flutter/Android shell work. These are instructions, not evidence that a tool or build has run. Use `tool/mobile/windows-g1-preflight.ps1` after setup; it is read-only. No Flutter app source has been created on the Linux agent because that host cannot build or test it.

## 1. Install free tools

Open PowerShell. `winget` is included with current Windows 11 App Installer; check it first. Install Git and Android Studio from their package IDs, and reopen PowerShell after installation:

```powershell
winget --version
winget install --id Git.Git -e
winget install --id Google.AndroidStudio -e
git --version
```

In Android Studio’s first-run wizard, choose the standard installation. In **Tools → SDK Manager**, install Android SDK Command-line Tools, Platform-Tools, and Android Emulator. Do not guess a project’s `compileSdk` or build-tools version: install the version generated by the selected Flutter template after the app is created.

Install Flutter in a short path outside the repository. The `stable` branch is used only to bootstrap a current SDK; record its exact Git commit and the version output before implementation, then keep that SDK fixed during G1 verification. Do not run `flutter upgrade` midway through a build/test cycle.

```powershell
$FlutterRoot = 'C:\src\flutter'
New-Item -ItemType Directory -Force -Path 'C:\src' | Out-Null
if (-not (Test-Path -LiteralPath $FlutterRoot)) {
    git clone --depth 1 --branch stable https://github.com/flutter/flutter.git $FlutterRoot
}
$env:FLUTTER_ROOT = $FlutterRoot
$FlutterBin = Join-Path $FlutterRoot 'bin'
$UserPath = [Environment]::GetEnvironmentVariable('Path', 'User')
$UserPathEntries = @($UserPath -split ';' | ForEach-Object { $_.Trim().TrimEnd('\') })
if ($UserPathEntries -notcontains $FlutterBin.TrimEnd('\')) {
    $UserPath = "$FlutterBin;$UserPath"
    [Environment]::SetEnvironmentVariable('Path', $UserPath, 'User')
}
[Environment]::SetEnvironmentVariable('FLUTTER_ROOT', $FlutterRoot, 'User')
$env:Path = "$FlutterBin;$env:Path"
flutter --version --machine
git -C $FlutterRoot rev-parse HEAD
& (Join-Path $FlutterRoot 'bin\cache\dart-sdk\bin\dart.exe') --version
```

Flutter supplies the Dart SDK for the app. Do not install a separate Dart SDK into the Flutter app’s PATH. The repository’s existing `sim/mesh_sim` package has its own `^3.4.0` constraint; that does not select the Flutter version.

## 2. Android SDK, PATH, Java, and licenses

In Android Studio, open **SDK Manager** and confirm its actual SDK location (normally `%LOCALAPPDATA%\Android\Sdk`). Install **Android SDK Command-line Tools**, **Platform-Tools**, and **Android Emulator**. After the Flutter project exists, install the platform/build-tools versions its generated Gradle files request.

Set the user Android SDK path and update the current PowerShell session. If Android Studio shows another SDK path, use that path instead of the default below:

```powershell
$SdkRoot = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
[Environment]::SetEnvironmentVariable('ANDROID_HOME', $SdkRoot, 'User')
$env:ANDROID_HOME = $SdkRoot
$SdkPathAdditions = @("$SdkRoot\platform-tools", "$SdkRoot\cmdline-tools\latest\bin")
$UserPath = [Environment]::GetEnvironmentVariable('Path', 'User')
$UserPathEntries = @($UserPath -split ';' | ForEach-Object { $_.Trim().TrimEnd('\') })
foreach ($Entry in $SdkPathAdditions) {
    if ($UserPathEntries -notcontains $Entry.TrimEnd('\')) {
        $UserPath = "$Entry;$UserPath"
        $UserPathEntries += $Entry.TrimEnd('\')
    }
}
[Environment]::SetEnvironmentVariable('Path', $UserPath, 'User')
$env:Path = "$FlutterRoot\bin;$SdkRoot\platform-tools;$SdkRoot\cmdline-tools\latest\bin;$env:Path"
flutter config --android-sdk $SdkRoot
flutter doctor -v
flutter doctor --android-licenses
```

Review and accept the Android SDK license prompts interactively. The preflight script does not accept licenses or change environment variables.

**JDK/AGP compatibility:** Do not copy a fixed Java/AGP/Gradle version tuple from another project. Android Studio includes a JBR/JDK; `flutter doctor -v` reports the Java binary Flutter selects. After generating the Android project, inspect its AGP declaration and Gradle wrapper, then verify the selected JDK against the official AGP compatibility requirements and the generated Flutter template. If a compatible JDK is needed, use Android Studio’s bundled JBR or a free JDK distribution selected for that AGP; do not set a persistent `JAVA_HOME` until the selected runtime is confirmed. For the default Android Studio install, set the chosen compatible JDK in this PowerShell session only (change the path if the installation differs):

```powershell
$JdkHome = Join-Path $env:ProgramFiles 'Android\Android Studio\jbr'
$env:JAVA_HOME = $JdkHome
$env:Path = "$JdkHome\bin;$env:Path"
java -version
javac -version
```

From the generated `android` directory, verify the actual Gradle runtime with:

```powershell
Set-Location .\mobile\app\android
Get-ChildItem . -Recurse -File -Include *.gradle,*.gradle.kts | Select-String -Pattern 'com\.android\.application|com\.android\.tools\.build:gradle|compileSdk|buildToolsVersion'
Get-Content .\gradle\wrapper\gradle-wrapper.properties
.\gradlew.bat --version
```

## 3. Read-only preflight

From the repository root, run:

```powershell
$Preflight = & .\tool\mobile\windows-g1-preflight.ps1 -ProjectRoot .\mobile\app
$Preflight
$Preflight.ExitCode
```

`ExitCode` 0 means the script found no missing required components; warnings can still require action. `ExitCode` 1 lists missing components. The script only inspects commands, paths, and local version/license metadata. It does not install, write settings, invoke `sdkmanager`, accept licenses, start an emulator, or enumerate devices. It cannot certify AGP/JDK compatibility; use `flutter doctor -v` and the generated Gradle wrapper for that.

## 4. Create/select an emulator and debug a phone

In Android Studio open **Tools → Device Manager → Create Device**, choose an owner-approved Pixel profile, and install a current stable x64 system image compatible with the SDK/template. Do not pin an API level until the project’s supported Android range is selected. Then:

```powershell
flutter emulators
# Copy an emulator ID from the command above:
$AvdId = '<ID-FROM-flutter-emulators>'
flutter emulators --launch $AvdId
flutter devices
adb version
adb devices -l
```

For a physical Android phone, enable Developer Options and USB debugging, connect USB, unlock the phone, and accept its RSA authorization prompt. Verify it without publishing the device serial:

```powershell
adb devices -l
flutter devices
```

An emulator verifies UI/build and some lifecycle behavior; it does not prove physical BLE, background delivery, or interoperability.

## 5. Create and exercise the app shell

Before G1 Dart source is added, create the project only if `mobile\app` does not exist. Flutter’s generated starter is a counter demo—not DumanMessenger G1. Do not run `flutter create` over existing app source without reviewing/backup of the diff, do not call the demo complete, and do not publish it. Use a locally provisional package ID only; choose the permanent Google Play application ID before release.

```powershell
$AppRoot = Join-Path (Get-Location) 'mobile\app'
if (-not (Test-Path -LiteralPath $AppRoot)) {
    New-Item -ItemType Directory -Force -Path .\mobile | Out-Null
    flutter create --project-name duman_messenger --org com.example --platforms android $AppRoot
}
```

Once the actual G1 source is present, run from the app directory:

```powershell
Set-Location $AppRoot
flutter pub get
flutter analyze
flutter test
flutter devices
# Set this to the emulator/device ID shown by flutter devices:
$DeviceId = '<DEVICE-ID-FROM-flutter-devices>'
flutter run -d $DeviceId
flutter build apk --debug
```

The debug APK uses debug signing; do not create or commit a release keystore. The commands above have **not** been run by the Linux agent. `flutter create` chooses the Android Gradle plugin/wrapper for that selected Flutter SDK; inspect and verify the generated values before changing them.

## 6. Minimal G1 source boundary

The first app implementation should contain only the following source/tests, with Flutter SDK widgets and `flutter_test`—no runtime plugin or service dependency:

```text
mobile/app/lib/main.dart
mobile/app/lib/app.dart
mobile/app/lib/screens/onboarding_screen.dart
mobile/app/lib/screens/conversation_list_screen.dart
mobile/app/lib/screens/diagnostics_screen.dart
mobile/app/lib/screens/settings_screen.dart
mobile/app/test/app_navigation_test.dart
mobile/app/test/onboarding_widget_test.dart
mobile/app/test/conversation_list_widget_test.dart
mobile/app/test/diagnostics_redaction_test.dart
mobile/app/test/settings_widget_test.dart
```

Onboarding says messaging is not available and performs local navigation only. The conversation list is an honest empty state. Diagnostics exposes only non-sensitive app/platform/build facts. Settings provides a session-only system/light/dark theme choice and a diagnostics link; it does not persist preferences. Tests cover navigation/back, empty-state wording, diagnostics redaction, and settings behavior. No identity, keys, crypto, contacts, messages, network, permissions, BLE, Wi-Fi Direct, or mesh forwarding belongs in G1.

These files are **not created yet**. The Linux agent lacks Flutter/Dart/Java/Android tools, so writing them here would be an unbuilt scaffold. Start them after the Windows preflight passes and the selected Flutter template/version can be built. The absence of a Mac does not block shared Dart source, Android tests, or an Android debug APK.

## 7. iOS build strategy without a personal Mac

The repository is public, but GitHub reports its current `CI` workflow as **disabled manually**; its existing jobs all use `ubuntu-latest`, with no macOS job. No workflow was enabled or changed. GitHub’s `actions/runner-images` table currently lists macOS 26 Arm64 under labels including `macos-latest`/`macos-26`, and macOS 15 Arm64 under `macos-15`; it also records macOS 14 retirement on 2026-11-02. Labels, installed Xcode versions, and pricing/eligibility change, so select a runner only after checking the live image README and compatibility with the chosen Flutter release. `macos-latest` is a moving label.

Preferred first option, if owner-authorized: a GitHub-hosted macOS runner for `flutter test` and an iOS Simulator build. It needs Actions to be re-enabled by an authorized repository owner; no cost/quota assumptions are made here. Alternative hosted Macs (for example, a MacStadium service or an AWS EC2 Mac host) require owner-controlled accounts and may incur charges; neither is authorized or used. Do not enable workflows, store signing secrets, or start paid services without explicit approval.

An iOS Simulator build does not require App Store distribution signing. A physical iPhone debug install requires an owner-controlled Apple development team/signing and provisioning setup. App Store publication remains unauthorized and is not part of G1. No iOS build or simulator test has passed.
